# 项目网页

GitHub Pages 继续使用 `docs/`，无需构建步骤或外部运行依赖。

- `index.html`：项目首页，用轻量的双通知概念动画介绍桌面提醒与手机消息，下方提供安装方式、通知渠道与常见问题。首页独立呈现，不嵌入完整演示的 iframe。
- `demo.html`：独立宽屏演示。播放器使用 16:9 画布，画面中的 macOS 风格笔记本屏幕采用 16:10 比例。
- `assets/site.css` / `assets/site.js`：首页样式、主题、安装标签和复制命令。
- `assets/home-demo.css` / `assets/home-demo.js`：首页两张通知概念卡片的画面与播放行为。
- `assets/demo.css` / `assets/demo.js`：完整演示的场景、时间轴和播放控制。
- `llms.txt`：面向安装 Agent 的纯文本指南，官网和 README 的安装提示词共同引用。
- `assets/readme-hero-light.svg` / `assets/readme-hero-dark.svg`：README 的自适应主题头图，与官网共用品牌配色。
- `dsh-index.json`：现有插件索引，网页改版不改变此地址或内容。

## 本地预览

在仓库根目录启动静态服务器：

```bash
python3 -m http.server 8000
```

打开 `http://localhost:8000/docs/`。独立演示位于 `http://localhost:8000/docs/demo.html`，可以使用播放器的全屏按钮。首页两张场景卡片的“看完整演示”会在新标签页打开对应场景。

使用 HTTP 静态服务器预览，便于检查与 GitHub Pages 一致的相对资源路径和剪贴板行为。

## 两个独立场景

完整演示默认播放长通知场景，两个场景各自循环，通过场景按钮切换，不会自动衔接。

| 场景 | 演示时长 | 内容顺序 |
| --- | --- | --- |
| 长通知 `long` | 24 秒 | 用户交付较难任务 → 电脑画面变暗、时间快进 → 圆润人物喝咖啡、玩手机游戏 → 手机弹出通知 → 打开飞书查看项目和结果摘要 → 回电脑验收 |
| 短通知 `short` | 14 秒 | 三个独立 Agent 窗口并行工作 → 用户在不同窗口间切换 → 右上角出现 macOS 风格提醒 → 手动切回需要处理的窗口并继续操作 |

短通知场景使用三个独立窗口表现并行会话，不使用一个终端中的会话标签页。长通知场景通过人物离席和回到电脑的动作说明实际使用过程；手机上的游戏和飞书界面均为场景示意。

页面提供播放／暂停、重播、场景选择、进度拖动和全屏控制。重播从当前场景的开头开始，循环也留在当前场景。点击场景按钮会从该场景开头播放；启用减少动态效果时，切换场景会显示该片的代表性静帧，点击播放或重播才开始。焦点不在输入控件或按钮上时，也可按空格播放／暂停、左右方向键前后移动一秒。

### 静态审阅入口

可通过 `scene`、`t` 和 `paused` 参数直接打开某一场景的暂停画面：

| 相对 URL | 审阅画面 |
| --- | --- |
| `demo.html?scene=long&t=0&paused=1` | 长通知场景的起始画面 |
| `demo.html?scene=long&t=8&paused=1` | 人物喝咖啡、手机游戏与仍在工作的电脑 |
| `demo.html?scene=long&t=12&paused=1` | 游戏上方弹出飞书通知 |
| `demo.html?scene=long&t=16&paused=1` | 打开飞书，查看项目和结果摘要 |
| `demo.html?scene=long&t=20&paused=1` | 返回电脑检查变更与报告 |
| `demo.html?scene=short&t=3.4&paused=1` | 三个独立窗口与第一条 macOS 提醒 |
| `demo.html?scene=short&t=5.2&paused=1` | 手动切回需要回复的窗口 |
| `demo.html?scene=short&t=10.4&paused=1` | 切到测试窗口检查结果 |
| `demo.html?scene=short` | 直接播放短通知场景 |

`t` 单位为秒，相对于所选场景的起点计算，长场景范围为 0–24，短场景为 0–14。`paused=1` 用于静态审阅，不会自动继续播放。减少动态效果模式下，未传 `t` 时默认展示场景中间的静态画面；需要核对起始帧时应明确传 `t=0`。检查一个完整流程时，可以使用进度条逐段查看。

旧链接的 `scene=away` 对应 `long`，`scene=desk` 和 `scene=desktop` 对应 `short`。

## 主题与播放行为

默认跟随系统浅色／深色偏好。首页通过按钮依次切换“自动 → 浅色 → 深色”，演示页通过外观下拉框选择相同三种模式。选择保存在 `localStorage` 的 `cc-notify-theme` 中，取值为 `system`、`light` 或 `dark`；存储不可用时仍可在当前页面切换。

完整演示在标签页隐藏时暂停，恢复后继续当前进度。开启“减少动态效果”时默认静止，用户仍可主动播放。窄屏或偏竖的窗口显示横屏引导；恢复宽屏后按原先的播放／暂停选择继续，手动暂停不会被旋转屏幕覆盖。首页的安装说明在竖屏下仍可阅读。

首页概念动画与完整演示是两个独立页面的实现。修改其中一处时，应同时检查主题、减少动态效果和可见状态的处理。

## 产品能力与演示边界

演示中的任务时长和等待时间均经过压缩。页面不发送真实消息，不调用系统通知接口，也不申请通知权限。

- 通知中的项目、事件与摘要帮助用户识别待处理会话，返回对应窗口由用户手动完成。演示不应出现通知直达会话、自动切换 Agent 窗口或手机远程审批的交互。
- 长通知的默认 5 分钟延迟从插件收到宿主事件开始计算，与任务已经运行多久无关。人物离席、任务完成和消息送达应是可区分的步骤。
- 后续输入等宿主活动会清除对应会话尚未发送的提醒；已送达消息保留，其他会话继续独立排队。看到通知本身不构成取消信号。
- 手机通知卡片使用示例内容。维护字段时应核对 `scripts/notify.sh` 和 `scripts/channels/feishu.sh`，不要把 Agent 名称误写成实际执行工具名，或补入插件没有提供的会话链接。
- Claude Code、ChatGPT Codex 与 DeepSeek Harness 提供原生宿主事件；Magpie 观察网关请求与响应。演示的任务验收使用原生 Agent 场景，Magpie 的模型响应结束不能直接表示整个 Agent 任务结束。
- 网页示例中的手机渠道需由用户实际启用并配置凭据。渠道延迟、事件筛选与安装命令以仓库实现和兼容性文档为准。

## 修改后的检查重点

1. 浅色、深色与系统自动模式下，首页和演示主题一致。
2. 首页只展示轻量概念动画，完整演示入口可用；首页没有载入完整播放器的 iframe。
3. 默认进入 24 秒长通知场景，14 秒短通知场景可单独选择；各自循环、重播，播放结束不自动切换场景。
4. 暂停、拖动、场景选择、URL 静态审阅与全屏正常；静止模式不被自动播放覆盖。
5. 短通知使用三个独立窗口，提醒在桌面右上角出现；用户手动选择目标窗口，不点击通知跳转。
6. 长通知完整展示交付任务、变暗快进、喝咖啡与手机游戏、收到通知、打开消息和回电脑验收；通知信息与实际产品能力一致。
7. 全屏画布保持 16:9，笔记本屏幕保持 16:10；宽屏尺寸变化时主体和播放器控制可见。
8. 窄竖屏提示、横屏恢复、隐藏标签页暂停与减少动态效果正常。
9. 四个安装标签支持方向键、Home、End，复制成功有反馈；剪贴板不可用时可手动复制。
10. 禁用 JavaScript 后仍能阅读全部安装命令；相对资源路径在 `/cc-notify-hooks/` 子目录下可用。

node --check docs/assets/demo.js
git diff --check
