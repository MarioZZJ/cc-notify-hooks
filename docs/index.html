Claude Code

插件名 cc-notify-hooks · 本仓库自建 marketplace

在 Claude Code 中执行
/plugin install cc-notify-hooks --marketplace MarioZZJ/cc-notify-hooks

一条命令安装需 Claude Code 2.1.275 及以上。也可按 README 分别注册来源、安装插件。

安装后

  1. 运行 /reload-plugins 刷新插件。
  2. 执行 /cc-notify-hooks:config，选择渠道、填写凭证并设置延迟。

覆盖权限提醒、结构化提问、回复结束及异常事件。详细取消边界见下方兼容性说明。

Codex CLI

插件名 cc-notify-hooks · 本仓库自建 marketplace

在终端中执行
codex plugin marketplace add MarioZZJ/cc-notify-hooks
codex plugin add cc-notify-hooks@cc-notify-hooks
此前关闭过 hooks？

Codex 0.169.0 默认开启 hooks。若曾关闭，在 ${CODEX_HOME:-~/.codex}/config.toml 的 [features] 中恢复：

config.toml
[features]
hooks = true

安装后

  1. 启动新会话，在 /hooks 中审阅并信任 hooks；桌面端可使用 Settings > Hooks。
  2. 使用插件的 config 技能或安装后的 setup 入口配置渠道。
  3. 插件脚本升级后，重新审阅 hooks。

更新来源与插件：codex plugin marketplace upgrade cc-notify-hooks。

使用 dsh 0.2.2-rc.3 或更新的兼容版本。新安装按 profile 注册；已有 home 级安装保留配置与兼容入口。

未启用热重载（HMR）时，重启对应宿主。普通 npm CLI 无法管理 desktop profile。

本地安装引用仓库目录，安装后请保留。远程来源需包含相应插件入口。

03 / 调度机制

每次发送前，
确认通知是否仍待发送

延迟队列按会话隔离。宿主报告后续活动后，清除对应会话或请求的待发标记，其他会话继续保留。

阅读工作原理 ↗

  1. 宿主事件进入队列

    接收权限等待、结构化提问、回合结束或网关响应等事件，为已启用的渠道创建待发标记。

  2. 到达延迟，检查标记后发送

    秒级渠道先提醒，分钟级渠道随后发送。每个渠道发送前都检查对应标记；标记已清除，就跳过发送。

  3. 宿主报告响应，取消余下提醒

    新输入、提问结束或支持的中断事件可触发清理。取消只作用于尚未发送的通知，已经送达的消息保留。

04 / 事件与兼容性

接入层不同，通知含义也不同

Claude Code、Codex CLI 与 dsh 观察原生宿主事件；Magpie 观察经过网关的模型请求。

完整兼容性说明 ↗
工具触发通知清理待发通知
Claude Code权限与等待提醒、结构化提问、回复结束、异常新输入、普通工具开始、工具成功或失败、提问结束、会话结束
Codex CLI权限请求、结构化提问、回合结束新输入、普通工具开始、工具完成、提问结束、中断、会话结束
dsh审批等待、结构化提问、正常回合结束、错误或输出限制审批决定、提问结束或取消、新输入、新回合、Agent 销毁、插件卸载
Magpie可识别的完整文本响应、模型请求错误同会话下一次网关请求

Magpie：模型响应完成 ≠ Agent 任务结束

一次模型响应可能只是多轮任务的一部分。工具调用响应不作为完成通知；审批按钮、用户回答和客户端中断需要原生 Agent 集成。查看网关限制。

取消时间取决于宿主提供的信号

Claude / Codex 的工具开始事件早于权限确认，不能保证点击审批按钮就立即取消。Codex 自动审阅也可能触发权限通知。宿主自身的等待时间另计；详细边界见 兼容性文档。
