01 / GET CONNECTED

让你的 Agent 学会叫你。

选择工具，安装插件，再启用你需要的通知。依赖 Bash、jq 和 curl；macOS 系统通知使用 osascript。

版本基准与安装限制 ↗

Claude Code

插件名 cc-notify-hooks · 本仓库自建 marketplace

在 Claude Code 中执行
/plugin install cc-notify-hooks --marketplace MarioZZJ/cc-notify-hooks

一条命令安装需 Claude Code 2.1.275 及以上。也可按 README 分别注册来源、安装插件。

安装后

  1. 运行 /reload-plugins 刷新插件。
  2. 执行 /cc-notify-hooks:config，选择渠道、填写凭证并设置延迟。

覆盖权限提醒、结构化提问、回复结束及异常事件。详细取消边界见下方兼容性说明。

Codex CLI

插件名 cc-notify-hooks · 本仓库自建 marketplace

在终端中执行
codex plugin marketplace add MarioZZJ/cc-notify-hooks
codex plugin add cc-notify-hooks@cc-notify-hooks
此前关闭过 hooks？

Codex 0.169.0 默认开启 hooks。若曾关闭，在 ${CODEX_HOME:-~/.codex}/config.toml 的 [features] 中恢复：

config.toml
[features]
hooks = true

安装后

  1. 启动新会话，在 /hooks 中审阅并信任 hooks；桌面端可使用 Settings > Hooks。
  2. 使用插件的 config 技能或安装后的 setup 入口配置渠道。
  3. 插件脚本升级后，重新审阅 hooks。

更新来源与插件：codex plugin marketplace upgrade cc-notify-hooks。

打开配置指南 ↗
  1. 01

    电脑前，用短通知

    macOS 默认 3 秒提醒；也可开启 Telegram、Bark 等手机推送渠道。

  2. 02

    经常离席，再加一个长通知

    启用飞书、企业微信或 Slack 等渠道，填写凭据。默认 5 分钟未响应时发送。

  3. 03

    需要完成提醒，订阅对应事件

    Claude Code、Codex CLI 与 dsh 的完成提醒使用 stop；Magpie 的网关响应与错误使用 notification。模板默认只开启 macOS 的 notification，请按需订阅事件、启用其他渠道。

03 / GOOD TO KNOW

几个你可能关心的问题。

让提醒按预期工作。

完整兼容性说明 ↗
通知会带来哪些信息？+

短通知提供工具、项目和简短摘要；结构化提问还可带问题数和 Session 标识。长通知补充事件、可用的工具与会话等定位信息，便于你判断接下来要处理什么。

点击通知，能直接跳回 Agent 吗？+

目前通知负责告知项目与上下文，返回对应会话由你手动完成。手机通知可在相应消息应用中打开；插件暂未提供会话直达链接或手机远程审批。演示中的鼠标会手动选择对应会话。

回来处理后，还会继续提醒吗？+

宿主报告新输入、提问结束或支持的工具／中断事件后，会清除对应会话的待发标记。已经发出的通知保留，其他会话继续独立排队。具体取消时机取决于宿主提供的信号。

四种接入方式有什么区别？+

Claude Code、Codex CLI 与 dsh 使用原生宿主事件，覆盖等待确认、结构化提问及回合结束等场景。Magpie 观察经过网关的模型请求和响应，下一次同会话请求会取消此前待发通知。

Magpie 的“模型响应完成”可能只是多轮任务的一步；整个 Agent 任务是否结束，需要原生集成提供的信息。原生 hooks 与 Magpie 同时启用会分别通知。
